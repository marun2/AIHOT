# 自动部署

本站部署在阿里云国内服务器 `/opt/myhot`，网址 https://hot.werdery.net ，由中台的 Caddy（`/opt/zhongtai/deploy/Caddyfile`）转发。

## 流程

```
推送到 main → GitHub Actions 跑测试（Check）→ 通过后 SSH 到服务器 → deploy/remote-deploy.sh
                                                                  拉代码 → 构建镜像 → 重启 → 检查网站
```

- 测试失败不会部署。
- 也可以在 GitHub 仓库 Actions → 部署 → Run workflow 手动部署。
- 在服务器上手动部署：`bash /opt/myhot/deploy/remote-deploy.sh`

## 服务器上的约定

- `.env`：所有密码、密钥和配置，只在服务器上，不进 Git。`EGRESS_PROXY_URL` 是香港中转代理，抓海外信源、拉代码、构建镜像都用它。
- `docker-compose.override.yml`：把 web 容器接入中台网络 `zhongtai_default`，让中台的 Caddy 能转发过来。只在服务器上，不进 Git。
- 不要在服务器上直接改代码：部署用 `git pull --ff-only`，服务器上有改动时会拒绝拉取。代码都在 GitHub 上改。

## 部署钥匙（只做一次）

在服务器上生成一把部署专用钥匙，并限定它只能运行部署脚本：

```bash
ssh-keygen -t ed25519 -N '' -C myhot-deploy -f /root/.ssh/myhot_deploy -q && echo "command=\"bash /opt/myhot/deploy/remote-deploy.sh\",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty $(cat /root/.ssh/myhot_deploy.pub)" >> /root/.ssh/authorized_keys
```

然后在 GitHub 仓库 Settings → Secrets and variables → Actions → New repository secret 添加：

| Name | 内容 |
| --- | --- |
| `DEPLOY_SSH_KEY` | `cat /root/.ssh/myhot_deploy` 的完整输出（含 BEGIN/END 两行） |
| `DEPLOY_KNOWN_HOSTS` | `echo "47.101.169.42 $(cut -d' ' -f1,2 /etc/ssh/ssh_host_ed25519_key.pub)"` 的输出 |
| `DEPLOY_HOST` | `47.101.169.42` |

填好后删掉服务器上的私钥副本：`rm /root/.ssh/myhot_deploy`。

不想再让 GitHub 部署时，删掉 `/root/.ssh/authorized_keys` 里 `myhot-deploy` 那一行即可。

## 同步原作者的更新

GitHub 仓库首页点 Sync fork → Update branch。合并进 main 后会自动测试并部署。原作者的更新说明见 `docs/deploy.md` 的“更新”一节，有需要手动处理的事项时先看一遍。
